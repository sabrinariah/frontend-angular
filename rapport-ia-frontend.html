1 Vue d'ensemble — Architecture IA

Le module IA du projet est composé de 4 éléments Angular interconnectés qui permettent à un utilisateur métier de décrire une règle douanière en français ordinaire, de la voir convertie automatiquement en code Drools exécutable, puis de la sauvegarder en base de données.

Deux chemins de création de règle
🤖 Chemin IA — NLP

L'utilisateur écrit une phrase libre en français → l'IA extrait automatiquement les conditions, l'action et la catégorie douanière → génère le code DRL Drools → l'utilisateur valide ou corrige avant la sauvegarde.

✎ Chemin manuel + aperçu DRL

L'utilisateur remplit le formulaire classique (code, nom, action, conditions) → un bouton "▼ Aperçu DRL" génère le code Drools correspondant en temps réel côté frontend, sans aucun appel au backend.

Détail de chaque étape
① Saisie — NlpInputComponent (mode "input")

L'utilisateur ouvre la modale via le bouton "🤖 Créer avec l'IA". Il saisit librement une phrase en français, ou clique sur l'un des 5 exemples pré-définis (inspection physique, taux UEMOA, circuit rouge, bon à enlever, valeur FOB). Un compteur de caractères s'affiche en temps réel.

② Envoi — NlpRegleService.convertir()

La méthode envoie un POST HTTP vers http://localhost:8081/api/nlp/convertir avec le corps {"phrase": "..."}. Un overlay de chargement IA s'affiche pendant l'appel avec le texte "Extraction des entités · Normalisation · Génération DRL".

③ Traitement backend — Extraction NLP (Spring Boot)

Le backend analyse la phrase et extrait : le champ, l'opérateur, la valeur, l'action douanière et la catégorie (TAXE, QUOTA, CERTIFICATION, VERIFICATION, CONTROLE, DOUANE). Il génère le code DRL Drools et calcule un score de confiance (0.0 à 1.0). Les ambiguïtés sont listées séparément.

④ Aperçu — Mode "preview" avec barre de confiance

Affiche : la phrase source, la barre de confiance colorée (vert ≥ 85%, orange 50–84%, rouge < 50%), les champs extraits, les conditions SI/ALORS, les ambiguïtés, et le code DRL Drools en section repliable.

⑤ Édition — Mode "edit" (optionnel)

Si l'utilisateur clique "✎ Modifier", tous les champs pré-remplis par l'IA deviennent éditables : code, nom, action, catégorie (liste déroulante chargée depuis l'API), conditions (ajout/suppression dynamique), statut actif/inactif.

⑥ Sauvegarde — POST /api/regles

Le payload est envoyé via RegleMetierService.create() avec le motif "Générée par IA — phrase : [phrase originale]" automatiquement archivé dans l'historique des versions de la règle.

Méthodes clés
convertir()

Appelle nlpService.convertir(phrase), active le spinner, reçoit le résultat, passe en mode "preview" et pré-remplit les champs d'édition via preparerEdition().

preparerEdition(res)

Mappe le résultat IA vers les champs éditables. Recherche la catégorie correspondante dans la liste par comparaison du champ categorieType.

valider()

Validation directe depuis le mode "preview". Si la catégorie n'a pas été trouvée automatiquement, redirige en mode édition avec un toast d'avertissement.

sauvegarderEdition()

Sauvegarde depuis le mode édition avec validation complète. Ajoute le motif "Générée par IA (modifiée) — phrase : ..." dans l'historique des versions.

pourcentageConfiance()

Convertit le score float 0.0–1.0 en pourcentage entier 0–100. Utilisé pour la barre de progression et l'étiquette textuelle de confiance.

ajouterCondition() / supprimerCondition(i)

Gestion dynamique des conditions en mode édition. Ajoute une condition vide ou supprime celle à l'index i de editConditions[].

Exemples de phrases douanières pré-définies

  • "Si le pays d'origine est le Sénégal, appliquer un taux préférentiel UEMOA de 5%"
  • "Si la marchandise est dangereuse, forcer automatiquement le circuit rouge"
  • "Si le paiement est confirmé et la marchandise conforme, émettre le bon à enlever"
  • "Si la valeur FOB dépasse 50 000 000 XAF, exiger une validation hiérarchique"
4 NlpRegleService — Communication backend

Service Angular minimaliste et dédié à la communication avec l'endpoint NLP du backend Spring Boot. Il encapsule l'appel HTTP et retourne un Observable typé.

Code source complet
src/app/core/services/nlp-regle.service.ts
@Injectable({ providedIn: 'root' })
export class NlpRegleService {

  private base = 'http://localhost:8081/api/nlp';

  constructor(private http: HttpClient) {}

  convertir(phrase: string): Observable<NlpConversionResult> {
    const request: NlpConversionRequest = { phrase };
    return this.http.post<NlpConversionResult>(
      `${this.base}/convertir`, request
    );
  }
}

6 DrlPreviewComponent — Visualisation Drools

Composant standalone de présentation qui affiche le code DRL Drools avec coloration syntaxique, numérotation des lignes, bouton de copie et une légende pédagogique expliquant chaque mot-clé Drools. Il est 100% stateless : il reçoit uniquement des @Input().

Inputs et comportement
@Input()TypeDescription
drlstringCode DRL brut (reçu du backend NLP ou généré localement)
phraseOriginalestringPhrase source affichée comme contexte en haut du bloc

Le composant découpe le DRL ligne par ligne via split('\n') et détecte le type de chaque ligne avec la méthode detecterType() : import, rule, keyword (when/then/end), variable ($var :), comment (//) ou code générique. Chaque type reçoit une couleur CSS distincte.

Points d'utilisation dans l'application
Dans NlpInputComponent (mode aperçu)

Affiché en section repliable via un bouton "▼ Afficher l'aperçu DRL". Le DRL provient directement du champ result.drl retourné par le backend NLP. L'utilisateur peut copier le code via le bouton "📋 Copier".

Dans RegleMetierComponent (formulaire manuel)

Affiché via le bouton "▼ Aperçu le code Drools (DRL)" au bas du formulaire. Le DRL est généré localement par la méthode genererDrl() — recalculé à chaque modification de champ via un getter Angular.

7 Générateur DRL local — RegleMetierComponent

La méthode genererDrl() permet de visualiser le code Drools d'une règle saisie manuellement, sans aucun appel backend. Le getter Angular drlGenere garantit un recalcul automatique à chaque changement de formulaire grâce à la détection de changements d'Angular.

Algorithme de génération (pseudo-code)
genererDrl(): string {
  // 1. Récupération des valeurs du formulaire
  code = selected.code || 'REGLE_CODE'
  nom = selected.nom || ''
  action = selected.action || 'ACTION'
  categorie = selected.categorie.type || ''

  // 2. Mapping opérateur Angular → opérateur DRL
  // IN → memberOf | NOT_IN → not memberOf | autres inchangés

  // 3. Formatage intelligent des valeurs
  // Numérique → sans guillemets (60, 50000)
  // Booléen → true / false
  // IN/NOT_IN → (val1, val2, ...)
  // Texte → "valeur entre guillemets"

  // 4. Construction du bloc conditions
  // Si aucune condition → $d : Declaration()
  // Sinon → $d : Declaration(\n champ op val,\n ...\n)

  // 5. Assemblage final
  return `package com.douane.rules;\nimport ...\nrule "${code}"\n...`
}

9 Exemples complets de code DRL généré
Exemple 1 — Inspection physique (score de risque > 60)

Phrase source : "Si le score de risque est supérieur à 60, déclencher une inspection physique obligatoire"

package com.douane.rules;

import com.douane.domain.Declaration;

// Règle : RISK_INSPECTION_001 — Inspection physique si score risque élevé
// Catégorie : CONTROLE

rule "RISK_INSPECTION_001"
    salience 10
    dialect "java"
when
    $d : Declaration(
        score_risque > 60
    )
then
    $d.setDernierResultat("INSPECTION_PHYSIQUE_OBLIGATOIRE");
    $d.setCodeRegle("RISK_INSPECTION_001");
    update($d);
end
Exemple 2 — Taux UEMOA (deux conditions : pays + valeur)

Phrase source : "Si le pays d'origine est le Sénégal et la valeur dépasse 1 000 000 XAF, appliquer taux UEMOA"

package com.douane.rules;

import com.douane.domain.Declaration;

// Règle : TAX_UEMOA_SEN — Taux préférentiel UEMOA Sénégal
// Catégorie : TAXE

rule "TAX_UEMOA_SEN"
    salience 10
    dialect "java"
when
    $d : Declaration(
        pays_origine == "SEN",
        valeur_marchandise > 1000000
    )
then
    $d.setDernierResultat("TAXATION_REDUITE");
    $d.setCodeRegle("TAX_UEMOA_SEN");
    update($d);
end
Exemple 3 — Validation FOB (valeur seuil haute avec IN)
package com.douane.rules;

import com.douane.domain.Declaration;

// Règle : DOC_VALIDATION_FOB — Exiger validation hiérarchique valeur élevée
// Catégorie : DOUANE

rule "DOC_VALIDATION_FOB"
    salience 10
    dialect "java"
when
    $d : Declaration(
        valeur_fob >= 50000000,
        regime_douanier memberOf ("IM4", "IM7")
    )
then
    $d.setDernierResultat("VALIDATION_HIERARCHIQUE");
    $d.setCodeRegle("DOC_VALIDATION_FOB");
    update($d);
end
