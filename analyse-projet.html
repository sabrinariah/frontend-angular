1. Vue d'ensemble du projet

ProcessFlow est une application web Angular dédiée à la gestion digitale des processus douaniers (import/export). Elle offre une interface centralisée permettant de modéliser des flux de travail BPMN, de gérer des règles métier basées sur des conditions logiques, de les générer à partir de phrases en langage naturel (NLP), et de piloter des dossiers d'import/export à travers des étapes structurées.

  • Paiement électronique et BAE
  • Taxation (UEMOA, CEDEAO, standard)

  • Conversion NLP → règle structurée
  • Export DRL (Drools Rule Language)
  • Versionnage des règles
  • Authentification Keycloak OAuth2

6. Fonctionnalité : Gestion des tâches

Les tâches sont les étapes d'un processus. Chaque tâche possède un formulaire dynamique, des règles de transition et optionnellement une logique de sous-processus (subprocess).

6.1 Structure d'une tâche

interface Tache {
  id?: number;
  nom: string;
  description?: string;
  assignee?: string;           // Responsable (rôle ou utilisateur)
  type: 'HUMAINE' | 'SYSTEME';
  statut: 'EN_ATTENTE' | 'EN_COURS' | 'TERMINE';
  ordre: number;               // Position dans le flux
  processusId: number;
  templateId?: string;         // Lien vers le catalogue de tâches
  formData?: string;           // JSON : champs, règles, valeurs, subprocess
}

6.2 Onglets de configuration d'une tâche

Onglet : Info
  • Nom et description
  • Type (Humaine / Système)
  • Assignee (responsable)
  • Statut courant
Onglet : Champs
  • Définir des champs de formulaire
  • Types : text, number, date, select, checkbox
  • Champs requis / facultatifs
  • Valeurs par défaut et options
Onglet : Règles
  • Règles de transition SI/ALORS
  • Mode simple (champ/opérateur/valeur)
  • Mode métier (règle externe)
  • Logique ET / OU
Onglet : Données
  • Valeurs remplies dans le formulaire
  • Prévisualisation des données saisies
Onglet : Subprocess
  • Branches OUI / NON
  • Tâches supplémentaires dans la branche
  • Flux parallèles et conditionnels

6.3 Règles de transition (RegleTransition)

Chaque tâche peut définir des règles de transition qui déterminent automatiquement la prochaine tâche à exécuter. 

interface RegleTransition {
  id: string;
  nom: string;
  modeRegle: 'simple' | 'metier';

  // Mode simple
  champId?: string;
  operateur?: OperateurCondition;   // ==, !=, >, <, >=, <=, contains, isEmpty
  valeur?: any;

  // Mode métier
  regleMetierIds?: number[];        // IDs des règles métier
  logiqueCombinaison?: 'ET' | 'OU';

  // Cibles de transition
  tacheOuiOrdres?: number[];        // Vers tâche(s) OUI (multi-cible possible)
  tacheSinonOrdre?: number;         // Vers tâche NON (loop-back possible)
  actif: boolean;
}

7. Fonctionnalité : Règles métier

Le composant regle.ts est le moteur central de règles de l'application. Il permet de créer, gérer, versionner et exporter des règles métier conditionnelles utilisées dans les processus douaniers.

7.1 Structure d'une règle métier

interface RegleMetier {
  id?: number;
  code: string;           // ex: "RISK_CIRCUIT_ROUGE"
  nom: string;            // ex: "Circuit Rouge – Inspection physique"
  action: string;         // ex: "Orienter vers circuit rouge"
  active: boolean;
  version?: number;
  categorie?: Categorie;  // TAXE, QUOTA, CERTIFICATION...
  conditions?: Condition[];
}

interface Condition {
  id?: number;
  champ: string;          // ex: "scoreRisque"
  operateur: string;      // ==, !=, >, <, >=, <=, contains, isEmpty, isNotEmpty
  valeur: string;         // ex: "60"
}

7.2 Fonctionnalités principales

CRUD complet
  • Créer une règle avec code, nom, action
  • Associer à une catégorie douanière
  • Ajouter des conditions multiples
  • Modifier / supprimer (avec confirmation)
  • Activer / désactiver
Versionnage
  • Historique de toutes les versions
  • Motif de modification obligatoire
  • Restauration d'une version antérieure
  • Numéro de version automatique
Génération DRL (Drools)
  • Conversion automatique règle → DRL
  • Aperçu du code généré
  • Syntaxe exécutable par le moteur Drools
Suivi d'utilisation
  • Liste des processus utilisant la règle
  • Compteur actif / inactif
  • Alerte si règle non utilisée

8. Fonctionnalité : NLP – Conversion de phrases en règles

Le composant nlp-input.component.ts permet à un utilisateur métier de saisir une règle en français naturel et d'obtenir automatiquement une règle structurée avec conditions et DRL.

8.1 Flux de traitement NLP

1. Saisie phrase  →  2. Appel POST /api/nlp/convertir  →  3. Résultat parsé + score confiance  →  4. Edition / Validation  →  5. Sauvegarde règle

8.2 Structure du résultat NLP

interface NlpConversionResult {
  regle: {
    code: string;
    nom: string;
    action: string;
    categorieType: string;
    conditions: Condition[];
  };
  drl: string;                // Code DRL généré automatiquement
  confidence: number;         // Score 0 à 1 (ex: 0.87 = 87%)
  ambiguites: string[];       // Liste des ambiguïtés détectées
  phraseOriginale: string;    // Phrase entrée par l'utilisateur
}

8.3 Niveaux de confiance

Élevé ≥ 85%

Création directe recommandée. L'utilisateur peut sauvegarder immédiatement.

Moyen 50–84%

Vérification des valeurs conseillée. Edition possible avant sauvegarde.

Faible < 50%

Révision manuelle obligatoire. Les conditions peuvent être incorrectes.

8.4 Exemples de phrases supportées

Phrase en françaisRègle générée
"Si le score de risque > 60, inspection physique obligatoire" RISK_CIRCUIT_ROUGE — scoreRisque > 60 → circuit rouge
"Si pays=Sénégal, appliquer taux préférentiel UEMOA 5%" TAX_UEMOA — paysOrigine == Sénégal → taxe 5% FOB
"Si marchandise dangereuse, forcer circuit rouge" RISK_MARCHANDISE_DANGEREUSE — marchandiseDangereuse == true

8.5 Fonctionnalités post-conversion

  • Édition du code, nom et action générés
  • Ajout / suppression de conditions manuellement
  • Changement de catégorie
  • Aperçu du DRL généré avant sauvegarde
  • Indicateur visuel du score de confiance (barre colorée)
  • Liste des ambiguïtés détectées

9. Fonctionnalité : Visualisation & Génération BPMN

L'application génère automatiquement des diagrammes BPMN 2.0 à partir des définitions de tâches et de règles de transition. Ces diagrammes peuvent être visualisés et téléchargés.

9.1 Service BpmnGeneratorService

bpmn-generator.service.ts transforme les tâches d'un processus en XML BPMN 2.0 complet incluant les éléments de diagramme (positions, connecteurs).

Éléments BPMN générés

  • Événement de début (StartEvent)
  • Événement de fin (EndEvent)
  • Tâche utilisateur (UserTask — type HUMAINE)
  • Tâche de service (ServiceTask — type SYSTEME)
  • Passerelle exclusive (ExclusiveGateway)
  • Flux de séquence conditionnels (SequenceFlow)
  • Sous-processus (SubProcess)

Diagramme Interchange (DI)

  • Calcul automatique des positions X/Y
  • Génération des points de passage (waypoints)
  • Labels sur les flux conditionnels
  • Tailles standardisées des formes

9.2 Composant BpmnViewer

bpmn-viewer.ts intègre la librairie bpmn-js pour afficher interactivement les diagrammes dans le navigateur.

  • Chargement depuis XML ou URL
  • Auto-fit du diagramme dans la fenêtre
  • Zoom et déplacement interactifs
  • Chargement dynamique à la demande
  • Export du fichier .bpmn

9.3 Circuits douaniers représentés

Circuit Vert

Score ≤ 30. Traitement rapide sans contrôle physique.

Circuit Orange

Score 31–60. Contrôle documentaire obligatoire.

Circuit Rouge

Score > 60 ou marchandise dangereuse. Inspection physique.
